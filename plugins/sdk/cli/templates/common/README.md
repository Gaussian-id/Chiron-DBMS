## Develop

With Node.js 22+ and the backend compiler installed, run the browser development host without Chiron Horizon:

```bash
chiron-horizon-plugin dev --path . --port 5190
```

The CLI builds the backend and loads the declared UI. Optional `[dev]` `ui_build` and `ui_watch` command arrays configure frontend builds. Development credentials are stored as local plaintext in `.chiron-horizon-dev/`; keep that directory out of commits and packages. Use the real Chiron Horizon host for final integration testing.

Build an installable candidate:

```bash
chiron-horizon-plugin package .
```

The command builds the native backend for the current host, stages `manifest.json`, `assets/`, and `ui/`, then writes an unsigned target-specific `.chiron-horizonp` candidate plus matching `.artifact.json` into `dist/`.

## Release

Build candidates with `chiron-horizon-plugin package .`, then publish them through your own GitHub release or custom repository. Sign packages with your repository key before distributing them to other users. An official Horizon plugin catalog and reusable publishing workflow are not configured in this release.

Do not submit ordinary plugin source to `Gaussian-id/Chiron-DBMS`; that repository accepts plugin host, SDK, CLI, schema, documentation, and official-example changes.
