## Develop

Edit `ui/index.html` and run the browser development host with Node.js 22+:

```bash
chiron-horizon-plugin dev --path . --port 5190
```

No backend or Chiron Horizon application is required. Open this plugin's workbench from the development shell; reload the page after edits. `.chiron-horizon-dev/` stores local development data and must not be committed or packaged. Use the real Chiron Horizon host for final integration testing.

Then package the plugin:

```bash
chiron-horizon-plugin package .
```

The command stages `manifest.json`, `assets/`, and `ui/`, then writes an unsigned universal `.chiron-horizonp` candidate plus matching `.artifact.json` into `dist/`.

## Release

1. Publish a GitHub Release. The generated workflow builds an unsigned universal candidate.
2. If this repository is registered with `autoUpdate: true`, Chiron Horizon Store automatically creates or updates a candidate PR. Otherwise, open one candidate PR against **`Gaussian-id/Gauss-DBM-store:main`** with the release and `release-candidates.json` URL; a submission Issue is not required.
3. After review, Chiron Horizon Store signs the approved candidate with the official repository key and updates the same PR with the installable asset and signed metadata.

Source code and the unsigned candidate stay in this repository. Chiron Horizon users install the Chiron Horizon Store-signed asset exposed by the official catalog.

Do not submit ordinary plugin source to `Gaussian-id/Gauss-Horizon`; that repository accepts plugin host, SDK, CLI, schema, documentation, and official-example changes.
