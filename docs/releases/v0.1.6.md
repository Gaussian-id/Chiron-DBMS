# Chiron Horizon 0.1.6

This release brings the stable upstream 0.6.31 database tooling into Horizon while preserving native ChironDB workflows, profile migration, the Horizon identity, and English documentation.

The 0.1.3, 0.1.4, and 0.1.5 tags were held back by release checks. Version 0.1.6 includes the backup, checksum, runtime, and offline-bundle corrections and is the public release of this integration.

## Highlights

- Keeps raw artifact metadata inside offline ZIPs so Horizon can verify and import their JARs, native agents, runtimes, and remote SQLite workers. Every offline bundle is checked against its actual contents before publication.

- Preserves pinned Go dependency checksums byte-for-byte, validates checksum structure during branding checks, and verifies fresh dependency downloads before release tagging.
- Corrects Windows Java runtime packaging and tests managed Java runtime creation on all four desktop platforms before publication.

- Releases scheduled-backup worker locks explicitly on shutdown, drain, cancellation, and failed startup, preventing inherited handles from delaying leadership transfer.
- Integrates upstream improvements since 0.6.16, including the split Rust workspace, plugin runtime and development tools, query/result handling, database metadata, and driver updates.
- Registers 86 database connection types and 110 profiles, including Solr, NebulaGraph, Salesforce, and Transwarp Inceptor, with explicit access and Schema Viewer capabilities.
- Retains native ChironDB HTTP and ChironQL support, collection browsing, sequential scripts, run-local `USE`, and per-statement write approval.
- Restores the native ChironDB assistant in the updated conversation UI: parser-validated reads, exact write approval, cancellation, durable history, attachments, and consent-scoped result sharing.
- Preserves ChironDB Relational over PostgreSQL wire, context-aware Schema Viewer modes, the database version monitor, and the Poppins/Black Horizon appearance.
- Keeps relational queries working by using PostgreSQL-compatible schema cleanup supported by ChironDB’s SQL subset.
- Protects AI credentials during upgrades and encrypted sync imports, including proxy credentials and CLI environment variables. Provider changes cannot reuse secret references from a different destination.
- Corrects plugin package names and SDK host-version requirements, Java manifest validation, release asset naming, and the new native driver packaging.

## Upgrade and distribution

Existing Horizon profiles stay in place. Legacy profiles and exported formats retain their compatibility paths. Back up your profile before upgrading and close the old application during migration.

Desktop downloads are provided for macOS arm64/x64, Windows x64, and Linux x64, alongside driver assets and checksums. macOS builds use ad-hoc signing; Windows installers are unsigned. Automatic updates and package-manager publication remain disabled. Local signed plugins and custom repositories remain available; an official Horizon plugin catalog is not configured.

## Verification

The integration was checked with the frontend suite and focused regressions, desktop/documentation type checks, production frontend build, native desktop compilation, Rust core/credential/connector/plugin tests, Java and Go driver tests, and packaging checks. Disposable live ChironDB tests exercised reads, writes, approvals, cancellation, roles, reconnects, and multi-statement scripts. Browser verification confirmed the branded integration workspace and successful native ChironQL execution.

The preservation checklist and reproducible commands are in [the integration record](https://github.com/Gaussian-id/Chiron-DBMS/blob/v0.1.6/docs/development/upstream-0.6.31.md). The backup fix has a deterministic duplicated-handle regression, and Linux PR verification now includes the complete Rust core suite. Native CI builds and release asset verification are required before publication; cross-platform interactive acceptance is separate from compilation.
